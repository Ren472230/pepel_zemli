# Автономный цикл разработки по команде «запускай»

**Полномочия:** docs/autonomy.md. **Единственный источник:** GitHub. **Приоритеты:** docs/backlog.md. **Результаты:** docs/audits/, docs/status.md. Каждый запуск – конечная проверяемая работа, а не обещание фонового процесса.

## Алгоритм каждого запуска

1. Координатор читает AGENTS.md, канон, семь профилей ролей, очередь, решения, последний отчёт. Фиксирует дату и хеш базового коммита, сверяет состояние Sites по docs/release.md.
2. Программист и тестировщик запускают npm test, npm run audit (если среда способна исполнять код) и проверяют корректность доказательств. Технические тесты не считаются браузерным прохождением.
3. Исследователь проверяет 2–3 аналога по первичным источникам с ссылками и применимостью. Геймдизайнер проверяет 10–15 дней каждой расы, развитие, экономику, боссов и Катаклизм в доступной глубине.
4. Дизайнер проверяет 360/390/768/1366 px, масштаб 200%, мышь и касания, карту, бой и окна. Художник сверяет 84 портрета форм, четырёх героев и остальные ассеты с реестром и кадрированием.
5. Координатор объединяет находки, убирает дубли, сверяет канон и выбирает максимум одну независимую P0/P1-задачу для немедленного безопасного исправления, записывает владельцев файлов.
6. Программист создаёт рабочую ветку, воспроизводит ошибку и сначала добавляет падающий регрессионный тест. Затем минимальное исправление. Тестировщик проверяет изменения отдельно. При отсутствии средства проверки сообщают конкретный риск.
7. Проверки: npm test, npm run audit, манифест, миграция сохранений если затронута, браузер при наличии. До подтверждённых тестов не объединять с main.
8. При достаточных доказательствах открыть запрос изменений, проверить и самостоятельно объединить в main, если инструмент поддерживает это и отсутствуют конфликты. Публикация Sites выполняется отдельно только по проверяемому протоколу docs/release.md.
9. Обновить очередь, датированный отчёт, docs/status.md и решения. Сводку вывести в чат: статус семи ролей, подтверждённые находки, именно сделанные правки, доказательства, ограничения, ссылка на ветку/коммит и следующий выбранный шаг.

## Статусы

- Подтверждено проверкой – есть свежая команда или проверенный сценарий.
- Обнаружена проблема – есть шаги воспроизведения и фактический сбой.
- Гипотеза – предположение для теста или игровая идея.
- Требует проверки – нужный способ проверки отсутствует.
- Заблокировано – указан конкретный внешний фактор.

Отдельно учитывать: код, экономику, способности, первые дни, телефон, компьютер, изображения и удовольствие от игры. Не смешивать наличие изображений с их читаемостью, Node-модель с настоящим браузером и симуляцию с оценкой игрока.

## Роли и владение файлами

Координатор – AGENTS.md, docs/backlog.md, docs/status.md, docs/decisions.md. Программист – dist/index.html, dist/expansion.js, dist/expansion.css. Тестировщик – tests/, test-*.cjs, scripts/. Исследователь – docs/research/. Геймдизайнер – proposals и секции канона после утверждения; художник – dist/assets/ и assets-manifest.json; дизайнер – отчёты UX и задачи программисту. Общие документы изменяются только последовательной записью координатора.

## Передача между чатами

Сообщение «Работаем с https://github.com/Ren472230/pepel_zemli . Прочитай AGENTS.md и запускай» достаточно. При наличии старых чатов проверь актуальность их сведений по GitHub. Новые пользовательские решения переноси в GitHub.
