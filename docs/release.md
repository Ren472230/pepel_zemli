# Источник и публикация

Исходная перенесённая версия: Sites v10, коммит исходного хранилища c8d0ed1919db72d398bb9856ca5d8438f89ce143. Живая игра: https://ashen-realms-ren.teamwork-r-p-5423.chatgpt.site .

Основной код и документы ведутся здесь. Служебное хранилище Sites пока остаётся каналом доставки. Автоматическая синхронизация между ними пока не настроена.

При выпуске: проверить актуальный коммит GitHub; npm test; npm run audit; выполнить браузерные сценарии или явно указать ограничение. В чистой рабочей копии Sites открыть поддерживаемый процесс, перенести ровно dist/ проверенного коммита, сохранить существующий hosting.json и текущую аудиторию. Использовать навык Sites для упаковки, отправки и публикации. Проверить завершение публикации. Записать сюда исходный коммит GitHub, версию и результат. Не переносить старую копию dist/ поверх более новой без сверки изменений.

Текущая публикация остаётся с доступом владельца. Репозиторий публичный по существующим настройкам пользователя; секреты и данные сохранений сюда не входят.

## Воскресный выпуск – правило 15.10.2026

- **Расписание:** каждое воскресенье в 04:00 по Europe/Samara (Ижевск), первый запуск 18.10.2026.
- **Режиссёр** принимает список готовых изменений; **Координатор** фиксирует точный SHA и безопасную передачу; **Тестировщик** проверяет выпуск; исполнитель Work/Sites публикует при фактической доступности.
- Ежедневная разработка меняет GitHub, а не сайт. Промежуточные ошибки, непроверенные ветки и несогласованные изменения канона до публикации не допускаются.

### Порядок

1. Зафиксировать точный проверенный коммит main, сравнить его с последней подтверждённой живой версией. При отсутствии новых одобренных игровых изменений пропустить выпуск.
2. Проверить npm test и npm run audit на этом коммите или сопоставимый успешный GitHub Actions. Сверить манифест изображений, наличие точных игровых файлов и совместимость сохранений.
3. Получить действительный Work/Sites-доступ владельца. Проверить актуальную версию сайта и сохранение hosting.json, аудитории только владельца, пользовательских данных, возможности отката. Не перезаписывать чужую более новую сборку.
4. Через поддерживаемую процедуру перенести ровно dist/ одобренного коммита, выпустить и проверить в авторизованном игровом браузере: выбор расы, загрузку старого сохранения, карту, бой, изображения и доступ.
5. Записать дату, прежнюю и новую версии, хеш исходного коммита, тесты, ссылку на сайт, сохранение прежних прав и реальный результат в docs/release.md и docs/status.md.
6. При отсутствии Work/Sites, прав владельца, проверки или при конфликте оставить сайт без изменений и сообщить конкретный блокер. **Созданное расписание не гарантирует режим Work, модель GPT-6.1 и уровень мышления**: параметры проверяются в настройках Work и автоматизаций самого сайта.

**Текущее состояние:** воскресная задача создана и активна, но Work/Sites-модель и привязка к конкретному сайту не установлены через этот интерфейс. Фактическая новая публикация ещё не подтверждена.
