# Журнал решений

## 2026-10-15 – Главный источник контекста

Решение владельца: GitHub содержит всю устойчивую информацию проекта – канон, роли, инструкции, задачи, итоги проверок, состояние выпусков. Чаты ChatGPT выступают исполнителями и координаторами, а не хранилищем единственного экземпляра данных.

## 2026-10-15 – Самостоятельный цикл

Решение владельца: после команды «запускай» и в регулярных запусках ИИ самостоятельно находит следующие задачи и начинает безопасные исправления, без повторной просьбы «исправляй». Приоритет – уменьшить участие пользователя. Защитные ограничения изложены в docs/autonomy.md. Роли сохраняются в docs/roles/*.md; возможность параллельной работы определяется инструментами текущего запуска.

## 2026-10-15 – Ежедневный запуск

Создана регулярная задача ChatGPT на каждое утро, ориентировочно 08:00 в часовом поясе задачи. Она получает ссылку на GitHub и план полного автономного цикла. Каждый отдельный запуск должен сам подтвердить доступность подключённых инструментов и зафиксировать реальные действия. GitHub сам по себе пока не запускает ИИ-агентов и не публикует Sites.

## 2026-10-15 – Инварианты выпуска

Сохранять прогресс и аудиторию владельца, проверять живую версию после публикации. Коммиты игры и её публикация – разные события. Канон меняется только по отдельному решению владельца.

## 2026-10-15 – Режиссёр как главный продуктовый центр

Владелец добавил восьмую роль «Режиссёр / оркестратор». Теперь она первой после аудита анализирует проблемы, планирует и назначает задачи другим ролям через координатора, затем после независимой проверки принимает или возвращает результат. Координатор организует процесс и GitHub, но не подменяет продуктовый выбор режиссёра. Цель ближайших циклов – сделать существующую игру **полноценной, сбалансированной, интересной**, без обязательного расширения списка больших механик. Дорожная карта закреплена в docs/product-roadmap.md. Канон меняется только по отдельному решению владельца.

## 2026-10-15 – Отдельная еженедельная публикация

Ежедневная автоматизация обновлена под роль режиссёра. Создана отдельная регулярная задача на **воскресенье 04:00 по Europe/Samara**, начиная с 18.10.2026: проверенный кандидат из main → проверка Work/Sites и доступа владельца → публикация → проверка живого сайта → запись результата. Инструмент создания задач в этом сеансе не позволяет установить конкретные Work, GPT-6.1 или лёгкое мышление и не подтверждает привязку к Site. Поэтому возможная блокировка выпуска обязательна к учёту и сообщению.

## 2026-10-22 – совмещённая техническая проверка и граница приёмки

Режиссёр принял совместные автоматические проверки COMBAT-001 и контролируемого GAME-001 на `b49042a67a53ddc178267eca8a1cb9fe77dd7edd`: [CI](https://github.com/Ren472230/pepel_zemli/actions/runs/39730645833) выполнил `npm test`, `npm run audit`, 115 файлов изображений сохранились. GAME-001 подтверждён только как модель четырёх фиксированных 15-дневных маршрутов; реальная случайная карта, поведение соперника и браузер не проверены. Слияние с `main` и открытие нового PR отклонены защитными проверками подключённого инструмента, `main` на момент решения `33d50aa0ce54ab4ceebf93498e5eff858c47210d`. Без подтверждённой интеграции нет оснований менять статус живого выпуска. Следующий P1: интеграция после снятия блокировки, затем варианты случайных первых дней. Это решение не изменяет канон и правила сохранений.

## 2026-10-24 – единая интеграция вместо пустых веток

После доказательного аудита Режиссёр выбрал приоритет P1: завершить ранее проверенные COMBAT-001 и модельный GAME-001 одним запросом изменений. Предыдущая рабочая ветка на `43a57c7f5f730af6b2a427acbb3d33d8e6c75aa5` прошла [проверки 23.10](https://github.com/Ren472230/pepel_zemli/actions/runs/39906306025). Новый рабочий документ и любые изменения требуют CI на точном конечном SHA; только затем при отсутствии конфликтов допустимо слияние. Контролируемый маршрут с отключённым соперником и искусственной картой подтверждает программную жизнеспособность сценария, но не баланс случайных карт или интерес игрока. Браузер, канон, сохранения, Sites и аудитория не изменяются. Подробности: [цикл №9](audits/2026-10-24-cycle-09.md).

## 2026-10-25 – GAME-001, проверка восстановления после капитуляции

После аудита режиссёр выбрал P1: покрыть воспроизводимыми моделями 24 сгенерированные карты (четыре расы × шесть сидов), капитуляцию перед соперником, торговлю, 15 переходов и возврат в стартовое поселение. Новые механики и изменения боевого кода не нужны, пока отсутствует воспроизведённый дефект. Тест добавлен в обязательную проверку; [GitHub Actions №40166004854](https://github.com/Ren472230/pepel_zemli/actions/runs/40166004854) прошёл на `082d468ae976a1bc97a08db186f7c9ea6d88378a`. В этих моделях события и обычные столкновения пропускаются, а капитуляция вызывается в подготовленном бою. Успех подтверждает только ограниченный вариант восстановления, не баланс случайных схваток, настоящий браузер или удовольствие. Следующее решение GAME-001/P1: сценарии ранних боёв, потерь и реального восстановления; при дефекте сначала падающий тест. Пользовательские сохранения, Sites, доступы и канон не менялись.
