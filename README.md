## Локальная версия для друга

Один HTML-файл включает 84 формы юнитов, все 115 иллюстраций, стили, код и данные. Интернет и сервер для запуска не нужны. Дважды нажать на `pepel-zemli-offline.html` в Windows и открыть его в Chrome или Edge. Сохранения остаются только в браузере устройства и не синхронизируются с Sites; перед обновлением файла можно выгрузить игровой отчёт.

Сборка: `node scripts/build-offline.cjs offline/pepel-zemli-offline.html`. Проверка: `node tests/offline-build.cjs` и `npm test`. Автоматическая сборка доступна в GitHub Actions [«Офлайн-версия для друга»](.github/workflows/offline-friend.yml): скачать артефакт `pepel-zemli-offline`, распаковать архив и передать единственный HTML-файл. Артефакт хранится 30 дней; при необходимости запускайте workflow снова. Это копия кода GitHub на момент сборки, не публикация Sites и не отдельная сбалансированная редакция игры.

## Запуск и проверки

Нужен Node.js версии 22 или выше; сторонние пакеты не нужны. `npm test` запускает автоматические проверки. `npm run audit` выполняет их и сохраняет доказательный отчёт в docs/audits/latest.json и latest.html. Открыть HTML можно локально. Для игры: `python -m http.server 8000 --directory dist`, затем открыть http://localhost:8000 .

В новом чате: «Работаем с https://github.com/Ren472230/pepel_zemli . Прочитай AGENTS.md и запускай».

Команда запускает цикл: аудит → разбор режиссёра → работа восьми ролей → тесты → повторная приёмка → сохранение в GitHub. Пользователь разрешил автономные исправления по docs/autonomy.md. Ежедневный запуск настроен через задачу ChatGPT; отдельно каждое воскресенье в 04:00 Europe/Samara назначена попытка выпуска Sites. Режим Work, выбор модели и доступность сайта следует подтвердить в настройках этого расписания; постоянно работающего сервера агентов пока нет. GitHub Actions проверяет ветки и запросы изменений. Публикация Sites отдельно и пока без автоматической синхронизации. Реальный игровой опыт оценивается отдельно от технических тестов.

## Структура

`dist/` – текущая игра и изображения; `tests/` – проверки; `docs/canon.md` – утверждённые правила и расхождения; `docs/roles/` – восемь ролей; `docs/audits/` – отчёты; `scripts/` – запуск проверок. `assets-manifest.json` – соответствие файлов изображений и контрольных сумм.
